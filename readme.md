### Структура БД
В БД есть 1 таблица `Olimpiad` со следующими колонками:
- id - по совместительству ключ и является id на самом сайте для нахождении олимпиады ==не может быть пустое== 
- name - Название олимпиады хранится в обычном тексте ==не может быть пустое== 
- grade - Классы обучения хранится в JSON формате в списке ==не может быть пустым==
- level - уровень олимпиады ==не может быть пустое==, но принимает значения: `1, 2, 3` в соответствии и `-1` если уровень не установлен
- rating - ==не может быть пустое== `REAL` число, содержит рейтинг олимпиады
- description - `TEXT` ==не может быть пустое==, принимает значение текста или `[]` если его нет
- link -  `TEXT`==не может быть пустое==  содержит ссылку на олимпиаду
- image_link - `TEXT` ==не может быть пустое==, но может содержать `None` если изображение не установлено
- subjects - `TEXT` ==не может быть пустое==, содержит список названий элементов в формате JSON
- events - `TEXT` ==не может быть пустое==, но может содержать пустой json список в случае если этапов нет или даты их проведения не определены (в графе "дата" на сейте написано "Уточняется")
> [!NOTE] Конвертирование из JSON
```python
import json
data = json.loads(RawData)
RawData = json.dumps(data)
```

### Events
В БД хранится в виде JSON информации, после преобразования в python является списком со словарями
**Структура словаря:**
- ID - номер по порядку
- DateType - Формат хранения информации, определяет временной промежуток проведения этапа:
	- noStart - Этап не имеет начала, можно трактовать как "до Х", где Х - число, которое будет храниться в `endDate` в формате UNIX
	- DeterminedRange - Этап имеющий начало и конец в формате UNIX
	- DeterminedDate - Определённый день проведения, хранится в `startDate`
- Name - название этапа
- startDate - Начало этапа, хранится в UNIX, если неопределенно то -1
- endDate - Конец этапа, хранится в UNIX, если неопределенно то -1
